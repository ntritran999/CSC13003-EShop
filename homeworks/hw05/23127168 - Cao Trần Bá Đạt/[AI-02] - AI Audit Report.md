### **4. Conclusion — When should AI be used (or not)?**

In conclusion, Claude provided a solid baseline for HW05 by scaffolding valid JMeter XML scripts and modeling core E2E user workflows. However, the AI failed to account for local environment constraints—proposing unrealistic thread loads (100–500 VUs) that triggered OS TCP socket exhaustion (ECONNREFUSED), attaching heavy visual listeners to CLI runs, and misinterpreting think-time throughput plateaus as hardware ceilings while proposing hallucinated fixes. Through manual refactoring, thread re-scaling, listener re-scoping, enabling SQLite WAL mode, and identifying the genuine 500 ms V8 GC stall during soak testing, we turned the boilerplate code into an accurate, reliable performance test suite. Ultimately, AI serves as an efficient starting tool, but human QA oversight remains essential for realistic load modeling, accurate metric interpretation, and valid architectural optimization.
