### **4. Conclusion — When should AI be used (or not)?**

In conclusion, Claude demonstrated strong capabilities in generating Playwright test scripts for HW04, successfully setting up robust baseline frameworks, selecting reliable fallback locators, and covering primary UI workflows across multiple features like login, checkout, and coupon management. However, the initial AI-generated implementations revealed critical structural and logical flaws when evaluated for long-term scalability and test reliability. Across FR-01, FR-09, and FR-17, the AI consistently omitted key edge cases from requirement specifications, struggled with stateful backend constraints—such as failing to reset the database, which caused flaky failures in sequential runs—and introduced unsuitable configurations like parallel execution that triggered race conditions on shared state. Additionally, its rigid assertion logic mishandled dynamic UI formatting like VND currency separators, while neglecting key data attributes in generated loops. Through manual refactoring—implementing automated database re-seeding hooks, switching to sequential execution (test.describe.serial), adopting flexible regex assertions, and expanding test coverage—we transformed the AI's boilerplate code into a highly reliable, isolated, and resilient test suite. Ultimately, while the AI provided a valuable starting foundation, human QA oversight remains essential to ensure complete coverage, state isolation, and accurate assertions in real-world automation testing.
