# AI Critique

Overall, the AI tool (Claude) had correctly followed the requirements and generated reasonable Playwright automation scripts. With context about the UI implementation of the pages through the JSX files, along with the list of test cases and the strict constraints for the final generation of automated test scripts, it provided tests that ran smoothly without any unwanted crashes. When producing the tests, the AI had correctly fell back to using CSS locators instead of more robust and resilient locators like getByLabel. This happened because the SUT(EShop) fundamentally lacks support for these better locators. The frontend codes do not have correct labeling structure for the input field, so naturally applying locators like getByLabel was not possible. Since the AI had to focus on tests creation while adhering to specified constraints, the final code given by the AI had some flaws in terms of the deisgn. In some cases, the final outputs included dense if-else statements, reduce the readability and the maintainability of the code. In another case, the generated tests for the data-driven test cases ignored a column in csv data file. While this did not result in incorrect test runs, it introduced fragility to the tests. The important lesson I had learned during this homework was to prepare enough context for the AI to help it produce the best outcome possible. I also learned that the test data itself played a critical role because when the data is wrong, not even the correct test scripts can result in wanted outputs.
