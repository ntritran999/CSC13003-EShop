# AI Critique

I used Claude for two contrasting tasks in HW04: generating the first Playwright implementation and writing a reusable automation skill. The coding response was fast and structurally useful. It created TypeScript specifications, external CSV data, three-browser configuration, and separate report commands. Nevertheless, I rejected that version as my final solution because polished structure hid important testing errors. TC_FR10_06 counted buttons and returned without clicking Cancel, so the testcase never performed its main action. FR-15 used positional selectors and a swallowed 1.5-second response wait, did not verify every important created field or cleanup result, and omitted Product CRUD authorization. FR-03 treated one generic weak-password message as evidence for several distinct password rules.

These problems occurred because the first prompt emphasized completing many scripts in a familiar reference format but did not explicitly require the AI to prove each action, distinguish browser validation from server rejection, or perform an adversarial review after generation. The model reproduced plausible automation patterns without fully checking their semantic meaning. Stateful orders and products also made isolation defects less obvious, while the SUT's generic password message limited the evidence any UI test could obtain.

The second response, `agents/SKILL.md`, was acceptable because the prompt included the lessons learned and strict constraints. The skill requires pasted UI and network evidence, incremental TypeScript generation, semantic selectors, deterministic waits, runtime CSV validation, cleanup verification, failure classification, and honest report gates. It also forbids claiming execution in a website-only chat. My main lesson is that AI should produce reviewable drafts, not trusted final tests. I must trace every testcase from input through action, response, persisted state, visible state, and cleanup, then accept the output only when I can explain and defend each assertion.
